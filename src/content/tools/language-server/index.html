Language Server.

Bring the components, tokens, and utility classes your team already publishes into the editor.

Local-first and editor-agnostic, the server reads existing manifests or discovers them from installed packages. It does not ask you to adopt a new all-in-one format.

First run

Connect your first manifest

You need VS Code and at least one existing component, token, or utility manifest. The extension reads your data; it does not generate these files.

  1. Install the VS Code extension, then open the workspace that uses your design system.
  2. For local manifests, add ds.config.json at the workspace root. Replace these example paths with your own and include only the source types you have:
{
  "sources": {
    "components": ["dist/custom-elements.json"],
    "tokens": ["dist/tokens.json"],
    "utilities": ["dist/utilities.manifest.json"]
  }
}
  1. Check the source you connected: in CSS, type var(-- for token suggestions; in HTML, start a component tag or a utility name inside class="". Suggestions should contain names from your manifest.

Installed packages with customElements or designSystem discovery fields in package.json do not need a config file. No suggestions? Confirm each configured path exists, then set dsLanguageServer.trace.server to messages and inspect the VS Code Output panel. Read the VS Code setup guide ↗
