Tokens v0.3

CurrentJSON SchemaStable

The token manifest describes a design system’s tokens, conditions, and supporting metadata. Start from a valid minimal document, then use the field reference for detail.

{
  "schemaVersion": "0.3.0",
  "tokens": []
}

Manifest fields

schemaVersion *string

States the Design Lasagna manifest format version.

Usage details

Use when: Always set this so readers and tools select compatible rules. View example

designSystemDesignSystemMeta

Describes the design system that owns this manifest.

Usage details

Use when: Attach a name, version, and documentation locations to a published manifest.

tokens *array

Lists the token records included in this resolved manifest.

Usage details

Use when: Add one record for each design token consumers should resolve.

conditionsarray

Defines the contexts in which a token value may change.

Usage details

Use when: A token needs a named theme, mode, platform, or other condition.

extensionsobject

Holds namespaced information not modeled by the core format.

Usage details

Use when: An integration needs additional metadata without changing the shared contract.

sourcesarray

Records files or upstream systems that contributed to this manifest.

Usage details

Use when: Consumers need a traceable path back to the authored token data.

generatedAtstring · date-time

Captures when a generated manifest was last produced.

Usage details

Use when: Publishing generated output where freshness matters to readers.

DesignSystemMeta

A nested definition with a stable anchor. Field types use its short name as a link instead of exposing the JSON Pointer.

Definitions should answer the minimum lookup question first, then reveal constraints and examples only when they help a reader make a valid choice.
