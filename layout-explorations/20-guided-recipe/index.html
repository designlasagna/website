Learn · 15 minutes · beginner

Publish your first token manifest.

By the end, you will have a small token manifest that is structured, validated, and ready to use with Design Lasagna tooling.

1Prepare the workspace.

Start in a project directory with Node installed. The guide tells readers what success looks like before asking them to make a change.

  • Node 20 or newer
  • A project directory
  • A text editor

2Create the smallest valid file.

Begin with a small manifest. A labelled code block makes the language and role clear without surrounding it in extra UI.

{
  "schemaVersion": "0.3.0",
  "tokens": []
}

3Name the design system.

Add only the information another person needs to identify the source. Keep the first change small enough that a validation error points to one clear cause.

{
  "schemaVersion": "0.3.0",
  "designSystem": { "name": "Northstar" },
  "tokens": []
}

4Validate before adding detail.

Run validation while the input is small. This keeps an error close to the change that introduced it, and makes a successful result easy to recognize.

npx @designlasagna/validator validate ./design-system.tokens.json --schema-version=0.3.0 --format=pretty

5Read an error as guidance.

If validation fails, use the filename, path, and expected type together. Correct the source file rather than trying to work around the command.

Common error

schemaVersion must be a string at /schemaVersion. Check that the version is quoted and that the validation command points at the file you edited.

6Verify the outcome.

Your result is a valid empty manifest with an identifiable owner. From here, add token records or continue to the guide on describing a design system.

  • File parses as JSON
  • Schema version is present
  • Design-system name is present
  • Validation completes without errors

Before you start
